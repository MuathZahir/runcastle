# ADR-0010: Laps (iteration without a mode)

- **Status:** accepted (2026-07-28)
- **Deciders:** Muath + grilling session
- **Spec delta:** `docs/SPEC.md` §15

## Context

The pipeline is one-way. Its single backward transition (`REVIEW_LOOP_BACK`,
review → implementation) exists so burns can *fix* what the spec already said —
there is no sanctioned path back to *changing what we're building* after the
human has test-driven it. That assumes the spec is right after one convergence,
which fails exactly when the human can't know what they want until they try it
— the common case for UI-shaped features. The missing loop: test-drive → learn
→ re-grill → update spec → burn again, until the human is happy.

A standing constraint shaped every choice below: the loop must never cost more
than it saves. If a lap's ceremony exceeds "I could've done that in a single
Claude session", the system has failed regardless of how principled its model
is.

## Decision

The pipeline **loops**; "agile" is not a mode. One trip around the loop is a
**lap**.

1. **Three verbs from review: Fix / Rethink / Merge.** *Fix* — the spec was
   right, the code wasn't: burn again via the existing review → implementation
   loop-back, same lap. *Rethink* — the code was right, the spec wasn't: a
   second typed backward transition (review → ideation) starts lap N+1.
   *Merge* — happy: G5, unchanged. A feature merged on lap 1 is exactly the
   old linear flow; "waterfall" and "agile" become descriptions of how a
   feature went, never settings.

2. **The loop closes on the feature branch.** Every lap's work accumulates on
   `feature/<slug>`; main is merged **once**, at the end. Test-drive mechanics
   and git topology are untouched. (Rejected: merge-every-lap — trunk-based
   discipline is a team virtue, not a solo-exploration one.)

3. **Rethink always lands in ideation.** Every lap opens by digesting what the
   drive taught, however briefly — that conversation is the point of the loop,
   so it always has a home. When the rethink is small the grilling is thirty
   seconds; the learning still lands in `decisions.md`, which is what makes
   lap 3's grilling smarter than lap 1's.

4. **Test-drive notes are quick-captured, then injected.** The test-drive
   panel gains a notes box; on stop, notes append to
   `docs/features/<slug>/test-notes.md` under a `## Lap N` heading (prose in
   the repo — the decision-5 seam, again). The next lap's session receives
   them in its injected context and starts *from* the observations, not from
   a blank page.

5. **Laps 2+ are one session by default.** Decision 9's unbroken-window rule
   applies to the whole lap: one terminal digests the notes, updates
   `decisions.md` and the spec, emits the lap's tickets via MCP, and
   auto-advances the phases as it goes. Human ceremony per lap: one
   conversation, two clicks (Burn, then Merge-or-loop). Full spread-out
   ceremony and the map (ADR-0001) remain available as opt-in escalation for
   genuinely big rethinks. No new `SessionKind`: the lap session reuses the
   existing `revisit` kind — its documented semantic (resume the conversation,
   amend docs + tickets) *is* a lap session — distinguished by a lap-purpose
   kickoff line and the session's lap tag. The embryonic review-bar "Iterate"
   (a revisit that emits fix tickets) is subsumed by Fix/Rethink.

6. **Notes promote to tickets in one click.** In review, notes render as a
   checklist; each has a "→ ticket" action (text editable inline). Promoted
   tickets join the **current** lap and Fix burns them — the cheapest lap type
   ("three obvious bugs") costs a few clicks and zero conversations. The lap
   session's context lists already-promoted tickets explicitly so it never
   re-emits them. Promotion is never required: Rethink is the catch-all, and
   its session can emit plain bug tickets too.

7. **Slicing is the grilling skill's judgment, not machinery.** The skill asks
   one standing question — *how sure are you this is what you want?* Sure →
   spec it whole, likely merge on lap 1. Unsure → thin lap 1 (walking skeleton
   of the uncertain part), consciously deferred scope parked in the spec's
   `## Later laps` section, which seeds the next lap's grilling alongside the
   test notes. (Rejected: an `agile`/MVP toggle — machinery for what is a
   conversational judgment.)

8. **Machinery is a counter plus tags.** `Feature` gains `lap: number`
   (starts 1; Rethink increments, Fix never does). `tickets` gains a `lap`
   column; sessions and events are tagged with their lap. G3/Burn scope to the
   current lap's tickets; G4 (`all-tickets-terminal`) needs no scoping —
   earlier laps' tickets are terminal by construction; G1/G2 stay dumb (on
   later laps they are trivially satisfied, and the lap *starts* with its
   grilling by construction — gates guide, they never imprison). The lap trail
   in the UI is **derived** by grouping tickets/sessions/events by lap.
   (Rejected: a `laps` table — a lap has no independent lifecycle; a row would
   be a mirror, and mirrors drift. Rejected: re-arming G1/G2 with
   modified-this-lap file heuristics — brittle machinery that trains the
   Override reflex.)

9. **The map was not generalized.** The map answers "this decision is too big
   to think through in one sitting"; laps answer "I can't know if I want this
   until I try it." Different problems, deliberately separate mechanisms; a
   mapped ideation can occur inside any lap. (Rejected: a `build` waypoint
   type spanning the lifecycle — it demolishes working phase/gate machinery to
   blur two distinct concepts.)

## Sequencing

Next feature after the 2026-07-28 push, dogfooded through runcastle itself —
with a thin lap 1 (Rethink transition + lap counter + one-session lap skill)
test-driven on a real feature, then note promotion + trail UI as lap 2. The
feature validates itself.

Open thread (tracked in CONTEXT.md, attacked independently): per-burn overhead
— sandbox spin-up and burner orientation — so laps never feel slower than a
bare Claude session (warm/reused sandboxes per feature, tighter burner
context).

## Consequences

- "Shipped" keeps meaning merged-to-main; nothing downstream of G5 changes.
- Review-phase UI becomes the feature's cockpit: notes checklist, three verbs,
  lap trail.
- The `## Later laps` spec section plus `test-notes.md` give every lap's
  grilling a concrete agenda for free.
- Ticket history is never destroyed; per-lap burn reporting ("lap 2: 4
  tickets, 4 done") falls out of the `lap` column.
- A feature can now live a long time between creation and merge; the feature
  branch grows long-lived by design (accepted: solo committer).
