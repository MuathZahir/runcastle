What was decided

Open one for the reason.

What is left out

Later

  • Workers’ screenshots: “Review keeps its screenshots”
  • The phone layout and back button: “Runcastle on your phone”
  • Telling you a file arrived: “Agents can notify your phone”

Not this feature

  • An accept button
  • Deleting a shown file
  • Copying a file’s neighbours along with it
  • Editing files, or a file browser
  • A PDF reader in the app, or code highlighting

Under the hood
MCP tool show_file: checks the path, copies to the thread’s shown/ folder, sorts the file
Thread log: one new event, file_shown, which already reaches every open client
Fold: foldThread gains a shown item between the work and the answer
Route: GET /api/threads/:id/files/:file, minted names only, never text/html
Web: ShownFiles and FileViewer, designed and waiting; wiring moves their types into core
Orchestrator: read_feature_chat lists shown copies; two skills gain a few lines

Built by the lead in its own checkout, with no tickets: the pieces form one chain through a few files, so workers would not run in parallel.
