A burn's last commit is never stranded in the sandbox

A ticket whose agent finished and committed either lands its work, or fails saying its commits were stranded. Never again a silent “agent made no commits” while the work dies with the container.

Under the hood

Sync hook (shared by the isolated clone and the cache slot): record HEAD, lease push and retry, then a plain push to refs/heads/<temp branch>. On success, delete any saved bundle; on failure, write a git bundle of the unsynced commits and one stderr line. Always exit 0.

Container setup: a saved bundle that follows from the checkout tip is fast-forwarded in and pushed before the agent starts.

Host, after each run or failed attempt: one new function collects a bundle onto the temp branch when it is missing or behind, else keeps it on its own branch; then checks the recorded HEAD is on the temp branch. Stranded beats “done” and “no commits”.

Tests: the real-git slot harness (deleted branch still syncs, broken remote saves, next setup takes it in, detached clone syncs) and real-git tests of the host function. Behaviour, not hook text.

Who builds it: the lead, in this checkout. No tickets: one file and its tests.
