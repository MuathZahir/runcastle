A burn's last commit is never stranded in the sandbox

A ticket whose agent finished and committed either lands its work, or fails saying its commits were stranded. Never again a silent “agent made no commits” while the work dies with the container.

Under the hood

Sync hook (shared by the isolated clone, the cache slot and the conflict resolver): record HEAD in the mounted workspace, lease push and one retry, then a plain push, all to refs/heads/<temp branch>. A push that succeeds deletes the record, so it only ever names unsynced work. On failure it appends the unsynced count and the error, and asks the agent to push once more. Always exits 0.

Burner: reads the record before each worktree goes and checks the branch holds that commit, on the normal path, the worktree-teardown path, the resolver verdict and the retry path. Stranded beats “done” and “no commits”.

Tests: a new real-git file that installs the hook in a real clone (runs on Windows too): deleted branch, detached HEAD, amend, squash and drop by rebase, no overwrite, hand push, resolver pass, retry notes. Shape tests updated.

Who builds it: the lead, in this checkout. No tickets.
