Opening a conversation

Showing a thread no longer waits on the agent 7.

Today
  1. Open the feature
  2. Resume screen, or "Resuming…"
  3. CLI starts in a terminal
  4. "The agent hasn't checked in yet"
  5. Read and type
After
  1. Open any thread: its history is there at once
  2. Type and send
  3. "Starting the agent…" under your message, only if it was idle

What runcastle sends an agent

Every message is a prompt into the thread, never keystrokes or a hidden run 6.

You→sent now; joins a running turn
Go, a round's end, Stop→waits for the turn to end; starts the chat if idle
The orchestrator→same queue
Self-planning→an ordinary thread you can watch; approvals auto-declined

The plan

I land the shared contract first, then two rounds of workers, then a review drive.

First · me
The thread contract

Thread events and the reducer that folds them into what the screen shows (in core), the shape of the thread API, and the agent host's interface. Workers build on it in parallel.

Round 1 · 3 at once
1Threads run over ACP: the agent host, Claude through its adapter, the thread log, the thread API, the feature chat and side threads.
2Codex over ACP, and a doctor check that each CLI is new enough for its adapter.
3The chat column on every page: the designed components wired to threads, the thread list, crops into the composer; Resume screens and terminal notices removed.
Round 2 · after round 1
4Everything else moves over: project, preparation, scenario and Fix-it chats; lead wakes and orchestrator lines as prompts; self-planning unattended; the headless and typed-terminal paths removed.
5Going back and controls: model, effort and fast mode; edit, rewind and branch; usage limits; titles, suggestions, drafts and export.
6Review: drive the app through every moment in the preview.
