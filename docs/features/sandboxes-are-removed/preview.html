Sandboxes are removed

Runcastle stops needing Docker. The container machinery, its images and caches, and every screen and setting made for it are deleted, and the first start after upgrading cleans up what containers left on disk.

The first start after upgrading

1 · Unfinished container workerIts commits are kept on a branch in the project, it is marked failed with a plain reason, and the lead is told. Its container stays, named with the command to remove it. 4
2 · Finished workers and the restOnly things labelled as this install's: finished workers' containers (conversation kept first), images, cache volumes, runcastle's own builders, project copies. 3
3 · TellUntil the human answers decision 3, this ships as tell-only: nothing is removed and the line names the exact commands. One timeline line with the space freed, and the one command for Docker's shared build cache, which runcastle does not touch. Runs once; no Docker means it does nothing.

Who builds what

No workers. The human asked features to build on their own to save memory and disk 2.
The lead, with its own subagents in parallel, on folders that do not overlap: server workers and boot (with the upgrade step); doctor, setup, CLI, config and API; the web app; docs, website and skills.
Review by the lead's own subagents against the brief and the repo's standards, then fixes, typecheck and the tests, then ready.

What is left out

Later

Not this feature

  • Making host workers work (merged already)
  • The workers-at-once default, its final home and the visible queue
  • Old features' history: stays readable, not migrated
  • CONTEXT.md and the ADRs: the orchestrator rewrites them
  • Deploying the website

Under the hood
  • Deleted: the sandbox engine, container scripts and push hook, the project copy and the fetch that landed commits, setup copy into containers, the in-container tool relay and guard, UID mapping, images and their build, the cache volume, the Dockerfiles and their packaging, the hourly container sweep, the shutdown stop.
  • Worker service: host path only; new rows record no engine; boot no longer resumes or wakes container workers.
  • Upgrade step: one small module, the only Docker caller left; runs once after migrations, best-effort, filtered by the runcastle.owner and runcastle.data-dir labels; keeps an unfinished worker's commits with plain git from its copy in the data folder.
  • Config: sandbox, sandboxImage, burnCpus, burnGuard, burnCache go and are ignored if present; burnConcurrency and setupCommand stay.
  • Database: one migration drops projects.sandbox, projects.sandbox_image, workers.engine, workers.container; preview port and dev-server columns stay.
  • Checks: repo typecheck; the upgrade step against a fake container CLI; host-only worker tests; doctor, setup plan, config load and web tests; a grep where every leftover Docker word is justified.
