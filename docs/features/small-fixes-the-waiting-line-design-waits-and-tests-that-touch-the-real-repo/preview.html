3 · Tests can't touch your real repo

What happened on 2026-11-02, reproduced in scratch repos 7

a git step in a worktree exports GIT_DIR→ a test run inherits it→ fixture runs git init, then stashes "keep me"→ your repo gets core.bare = true and the stash

After

test setup strips git's repo-location variables, once 6→ every git child works only in its scratch dir→ the run compares your repo's [core] config and stash before and after, and fails loudly if they changed 8

The two failing move tests are traced to a cause and fixed where it is 9. The stray "keep me" stash stays for you to drop 10.

Under the hood
  • Waiting line: delete the waiting-line component in the feature chat and its test file; drop the props the page passed only for it.
  • Design need: in core's featureNeed, a "design" wait with no recorded design waiting is treated as an "answer" wait. On the server, the Approve button's path clears a "design" wait when it empties the waiting designs.
  • Words: the feature skill's wait-kinds bullet, its design reference, and the wait_for_you tool description.
  • Strip: the worker setup file that already deletes RUNCASTLE_* also deletes git's --local-env-vars list.
  • Guard: a vitest global setup strips the same list in the main process, snapshots the real repo's [core] config and stash list, and throws at teardown if either changed.
  • Move tests: reproduce alone, in the full suite, and with an injected GIT_DIR/GIT_INDEX_FILE; fix the cause.
