How it gets built

Rounds of tickets, one at a time (this machine runs one agent at once). Workers can't build themselves: they don't exist in the installed runcastle yet.

  • 1

    Workers core

    The worker kind and record, start / message / hand back / land / send back / drop, the lead's tools, worker rows in the feature's context. The experimental setting goes.

    ticket
  • 2

    A worker's life

    The shared "agents working at once" limit and queue, needs-you pings, failure wakes, idle stop and wake, no ready with open workers, cleanup, previews through the pass-through.

    ticket
  • 3

    Inside the sandbox

    Your Claude setup and MCP servers, auto mode with its fallback, the worker's runcastle tools served from outside.

    ticket
  • 4

    Codex workers

    The same worker on Codex: its adapter in the sandbox, your Codex setup, auto-review, resume.

    ticket
  • 5

    Wire the screens

    Connect the approved designs to real data; old side chats read-only; the side-chat code removed; a scenario that seeds a feature with workers.

    ticket
  • ·

    The lead's instructions

    The offering rule, no more build tickets, the worker's own briefing. Written by me during the rounds.

    lead
  • 6

    Review round

    Drives the screens on the seeded scenario and reads the diff.

    review
  • ·

    Real sandboxes, by hand

    Sandboxes can't start Docker, so before ready I start real workers on this branch's server against a scratch data folder. Your checkpoint-2 drive runs the same way.

    lead

Under the hood
host sandbox (burn image, one per worker) ───────────────────────────────────── ────────────────────────────────────────── runcastle server own bare copy of feature/<slug> → its branch thread host ── docker exec -i ─────────▶ ACP adapter → Claude Code | Codex (auto mode) worker tools served over that stream ◀── hand back · dev server · read feature · show file · park design pass-through ── one 127.0.0.1 port ▶ dev server (must accept outside connections) landing queue ◀── fetch worker branch your setup, read-only: CLAUDE.md, rules, skills, workers table (status, handback) agents, plugins, MCP servers + logins; no hooks

The sandbox has no route to runcastle or the host repo; everything crosses the one exec stream or the one published port. Statuses: working · queued · needs you · handed back · landed · dropped · failed. The worker kind replaces the side kind; old side rows render read-only.
