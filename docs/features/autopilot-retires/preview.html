Upgrade

Who builds what

  • Me, the lead: all of it, in the feature's folder, as the epic asked (no workers). Subagents take parallel parts: server removal and permissions; merge, review and upgrade; web removals and the Start button; skills, scenarios and previews.
  • Review: my own subagents review the diff against the spec and the repo's standards; I fix, run typecheck and the affected tests, then say ready.

Under the hood
  • Deleted: the autopilot service, the set-autopilot tool, the "end autopilot" call, the hook that refuses typed prompts, the lock checks in sending, editing, waits, ready, notify and design approval, the web autopilot folder and marks, the autopilot previews and scenario.
  • Orchestrator rule: one check replaces the autopilot gate: own features only; create, start, read, dependencies, level, message pass; brief edits on drafts only. Merge, drive and stop tools leave its list; "plan feature" folds into start.
  • Start by level: one start path picks the interactive opening at Everything and the headless plan-and-build run below; the dependency-merge start calls it after cutting the branch.
  • Merge wake: every merge of an epic's feature wakes it; the message carries the review summary text, decided-without-you list and dismissed defects.
  • Clean review: the review stores whether checks passed; the merge at Nothing needs a completed review, checks passed on the newest, and no open defect.
  • Upgrade: an idempotent boot step moves autopilot epics' features at Everything to Nothing through the involvement service, returns epic-held waits to their features, then a migration drops the sessions' autopilot column.
  • Skills: project and feature skills lose autopilot, the run plan and the "Decided by autopilot" mark; hard-limit stops become their own rule; the lead's hand-back is for cross-feature trouble only.
  • Size: about 65 source and test files plus ~17 preview files.
