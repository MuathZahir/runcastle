Parked from the improve-workflow ideation (automatic review). Today per-branch isolation is a string-substitution convention ({{slug}}/{{branch}}/{{id}} rendered into driveEnv, cloning delegated to driveSetupCommand/driveStopCommand shell strings). That split — runcastle owns injection, the project owns cloning — is sound and should be kept; what is missing is affordances: no namespacing analogue for redis/queues/object storage, docker-compose stacks get no per-branch -p project name, no port remapping (fixed host ports collide across branches), no health-wait after setup, no {{port}} variable (explicitly out of scope in test-drive-improvements), hosted DBs (Neon branching, RDS) carry the whole burden in one shell string, and dotenv override:true silently defeats injection with no detection. This feature must NOT swallow: making the burner sandbox run apps/services (tickets stay hermetic), or any change to the automatic-review feature, which deliberately rides the existing drive machinery as-is.
