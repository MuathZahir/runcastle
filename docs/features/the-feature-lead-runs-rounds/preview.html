Under the hood

The lead's new MCP tools

  • dispatch_round({ seqs }) — today's startRun with explicit ticket ids. Refused while a run is active or a drive of this feature holds the slot.
  • stop_round() — landed work stays.
  • declare_ready({ scenario, whatToTest }) — building → review; warns, never refuses.
  • get_feature_context gains round history, autonomy mode, tokens.

The wake

  • run.finished + gate results → the feature's own lead.
  • Live: the orchestrator's waiter, opened to leads (asyncRewake on Claude Code, codex queue on Codex).
  • Not live: headless resume (claude -p --resume / codex exec resume).
  • No wake on a provider-limit halt. A live proof on both runtimes is required.

The engine, consumed not redesigned

  • Runs stop auto-advancing building → review.
  • verifyCommands run at every round end.
  • The review agent stops auto-minting fix tickets mid-run; findings go to the lead.
  • The lead's code commits ride the chat temp branch and land through featureLandingQueue, as chat docs already do.
  • Edit and install guards lift for the lead once the feature has left planning.

Data and settings

  • Round = run, numbered per feature. features.lap stays as a historical field.
  • Token usage per ticket and per session, summed over the session file (not the last message).
  • Autonomy: project column (default "Run until ready") + a new per-feature override.
  • Orchestrator: burn_feature becomes Go; start_feature_lap retires.
  • In-flight features get no migration.

Overturns, for the project session to record: one-chat-per-feature d3 (chat cannot burn); ADR-0010 (laps); charter decisions 9 and 15; "talk sessions do not write code" for the lead after Go; the brief's own budget (settled item 5) and the run time limit it absorbed.
