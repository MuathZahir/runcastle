Clicking a feature opens its lead

Clicking a feature opens its lead's chat and the sidebar stays on the features list. A small “3 ›” pill at the row's end goes down to the feature's workers page.

How it gets built

I build it myself→ Typecheck and tests→ One review round→ Ready, with screenshots

No worker tickets: it is one server count and one sidebar rule. The review round takes the screenshots you asked for: the list with pills, a click opening the lead, the pill opening the workers page, at desktop and phone width.

Under the hood
Server→the feature list gains, per feature, its live-worker count (needs you, failed, working, queued) and whether its workers page has anything, by widening the one grouped query that already counts working workers
Row→the sidebar row gains an optional pill slot, centred across both lines; the hover “…” sits left of it
Sidebar→goes down only after the pill was pressed for the open feature, until Back or another feature opens; a row click picks the worker the need names, else the lead
Phone→passes no pill; unchanged

Tested at the feature list, the row and the sidebar, where the existing tests already render them.
