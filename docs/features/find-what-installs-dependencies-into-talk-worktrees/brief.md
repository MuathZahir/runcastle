Charter decision 6 says interactive (ideation/spec/talk) terminals get instant **docs-only worktrees with no dependency install** — they only read code and write docs. A disk-full incident on 2026-09-25 measured 129 feature worktrees under `~/.runcastle/worktrees/<projectId>/<slug>` taking 19.4 GB, "mostly each worktree's own `node_modules`". So something installs dependencies into talk worktrees, contrary to the charter.

The sibling feature "Feature worktrees are removed on ship and archive" removes worktrees once a feature ships or is archived. That caps how long the cost lasts but not the cost itself: every in-flight feature still pays a full install. This feature is the root-cause question.

Candidates to check (none confirmed): the project's `setupCommand` (`bun install` for runcastle) running in the talk worktree rather than only in the burn sandbox; the launcher or `ensureTalkWorktree` running setup; a test drive or the project-level test drive installing into the worktree; sessions themselves (agents running `bun install` to typecheck or run tests from a talk session — the memory note about running tests in talk sessions suggests this happens); or a revisit/lap session doing so. The answer may be "sessions legitimately need deps sometimes", in which case the decision is whether to share one install (e.g. link to the checkout's node_modules) or accept it and rely on removal — and that decision may deserve an ADR amending decision 6.

Must NOT swallow: worktree removal on ship/archive or the boot sweep (sibling feature), or test-suite data-dir isolation (the "Test suite cannot touch the real data dir" feature). Start with diagnosis: find which code path or which session habit creates `node_modules` in `worktrees/<projectId>/<slug>`, with evidence, before deciding anything.
