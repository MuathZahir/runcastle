# Decisions — open findings survive laps: carry, link, or close

## 1. The lap session owns finding disposition; human paths stay as escape hatches
**Decision:** The Rethink/lap session is the primary owner of open-defect triage: it dispositions each open defect from earlier laps (link a new ticket, carry, or close-as-addressed) via a talk-session MCP surface. The existing human paths — the boundary triage's `quickFixFindingIds` promotion and the dismiss button — stay untouched as escape hatches.
**Why:** The session is the only party that knows whether its lap-N+1 tickets actually address a lap-N defect; a human clicking through a triage dialog is guessing. The machinery for the link path already exists end-to-end (`TicketInput.originFindingId` + the burner's `markFixProgress`), so session ownership reuses it rather than duplicating it in UI.

## 2. State model: link reuses `fixing`, carry mirrors notes, close-as-addressed is `fixed` + provenance
**Decision:** Link — a lap ticket emitted with `originFindingId` stamps `fixTicketId` on the finding and flips it to `fixing`; the existing burner lifecycle drives it to `fixed`/`failed`. Carry — a new `carried` status plus `carriedLap`, mirroring test notes: shown separately ("carried into lap N"), not counted as open, reopenable. Close-as-addressed — the finding goes to the existing `fixed` status with a provenance marker distinguishing a session attestation from a burner-verified fix (e.g. `resolvedBy: 'fix-ticket' | 'session'`), plus a short attestation note.
**Why:** "Addressed by lap N's work" IS fixed — a parallel `addressed` status would make every consumer (`defectState`, summary counts, badges) handle two names for one outcome. Provenance is kept because a burner-verified fix and a talk-session attestation are different evidence; the UI can surface the attestation without the counts caring. Carry copies the proven test-note shape rather than inventing a second carrying idiom.

## 3. One MCP tool: `resolve_finding`, on the ticket-writing session kinds
**Decision:** A single new MCP tool `resolve_finding({ findingId, disposition: 'carry' | 'addressed', note })` — `note` required for `addressed` (the attestation), optional for `carry`. Registered for `FEATURE_WRITE_KINDS`, the same kinds that get `emit_tickets`. Link needs no tool: it rides `emit_tickets` via `originFindingId`. Guards match `promoteOpenDefects` (must be an open defect of this feature). Carry stamps `carriedLap` = the feature's current lap. Reopening a carried finding is a human UI verb only — the session does not get it.
**Why:** One verb with a disposition argument keeps the tool roster small and the session's mental model flat; scoping to the emit-tickets kinds means any session that can shape the lap's work can also disposition the defects that work answers, with no new session-kind taxonomy.

## 4. Hard gate at `complete_phase(tickets)`: no un-dispositioned earlier-lap defects
**Decision:** `complete_phase(tickets)` fails while any defect from a lap earlier than the feature's current lap is still `open` (or `failed` with no live fix ticket), listing the offenders by title. Current-lap findings are untouched — they belong to the burner/review loop. Lap 1 passes trivially. The human can pre-empt the gate by dismissing findings in the UI.
**Why:** A soft warning recreates the exact stale-open drift this feature exists to kill. The check is cheap (the open view filtered to `lap < feature.lap`), the failure message names precisely what to do, and the session holds every tool needed to satisfy it — so there is no stuck state, only an unfinished triage.

## 5. Read model: current-lap counts, a carried section, carried-as-agenda for later laps
**Decision:** `viewByFeature`'s summary line and `openDefects` scope to the feature's current lap. Carried findings render in their own section (mirroring test-notes' `## Carried, still open`): "captured lap N, carried into lap M", outside the open count, with human reopen/dismiss verbs per card. Lap sessions see carried findings in `get_feature_context` alongside `openDefects` as agenda, not obligation: `resolve_finding` accepts `carried` findings too (link or close them), but the gate never forces re-carrying — carried stays carried until someone acts, same as carried notes.
**Why:** The all-laps view is the inflated "N still open" the brief observed; scoping makes the counts describe this lap's review. Forcing every lap to re-affirm each carried finding would turn carry into a nagging ritual; keeping them visible but optional matches the proven carried-notes semantics.
