Under the hood

A pure rule in core. A snapshot of one project goes in (started features, each with "running", "your move" and a reason; whether an orchestrator chat is running; whether anything is in Needs you); the alert line or nothing comes out. Running is read from the agent host and the run and worker queue, never from a stored status.

A watcher in the server, beside the needs watcher: re-checks a project on turn and wait events and on a one-minute timer, remembers per project when quiet began and whether this stop already alerted. After 10 minutes it sets a runcastle-marked wait on the target chat: the epic holding the stopped features, else the newest orchestrator chat, else the first stopped feature's chat. That wait's event already drives the phone ping.

Clearing. When work runs again it clears its own wait with a new cause, "work started again". A turn that only hits the usage limit again does not count. A server start counts as the start of quiet.

Tests. Table tests on the rule; watcher tests over the in-memory test database with a faked host and clock.
