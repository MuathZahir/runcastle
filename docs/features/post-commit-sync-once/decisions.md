# Decisions — post-commit-sync-once

## 1. Keep the push synchronous; delete the reset from the hook; remove the worktree host-side after the run
**Decision:** The isolated/slot post-commit hook becomes push-only (`git push origin HEAD:<tempBranch>`). The `git -C /home/agent/workspace reset --hard <tempBranch>` step is removed outright — not deferred, not moved. The mounted worktree is therefore always dirty at sandcastle's end-of-run check, so sandcastle preserves it (and never attempts its own `worktree remove`); the burner removes it host-side with the existing retrying `cleanupBurnWorktree`, on every exit path, after the BLOCKED.md / DIGEST.md harvest and before landing. No host-side `reset --hard` is performed — nothing reads that working tree.
**Why:** The reset is the expensive half (it stats every tracked file across the bind mount); the push is one pack write. Backgrounding the push was rejected: the push process lives in the container, which sandcastle removes seconds after the agent exits, so the *last* commit — the one that matters most — would be the one in flight, and in isolated mode the clone dies with it, leaving nothing on the host to reconcile against. Keeping the push synchronous preserves ADR-0005/0006's "commits survive a dead agent" property untouched. Audit of every consumer of the mounted worktree (sandcastle commit collection reads the ref only; later iterations clone/fetch through refs; worktree-name reuse never happens because attempt and resolver branches are unique; landing already detaches dirty pinned worktrees via `deleteBranchDetachingWorktrees`) found no reader of the working tree. Two side effects are positive: sandcastle's own `worktree remove` — the origin of the Windows `Directory not empty` teardown flake — no longer runs on the happy path, and the currently-unbounded pile-up of DIGEST-dirty preserved worktrees under `.sandcastle/worktrees/` gets cleaned.

## 2. A failed push retries once, then says one calm line
**Decision:** The hook retries the push once (short pause between attempts). If the second attempt also fails it prints a single stderr line — `runcastle: commit sync failed (will retry on your next commit); do not re-commit` — and exits. No `timeout` wrapper, no reconcile machinery, no other output. The prompt's existing "your commits sync back automatically" text stays as is.
**Why:** Git ignores a post-commit hook's exit status, so a failed push never fails the commit; the agent only sees stderr. A push of `HEAD` carries every not-yet-pushed commit, so a transient failure heals on the next commit — the one retry covers Docker Desktop hiccups, and the line tells the agent the truth without inviting the double-commit workaround seen in the audit. Silently swallowing failures was rejected: a genuinely broken mount would then surface only as a mystery "agent made no commits" with nothing in the transcript.

## 3. Amend ADR-0005 and ADR-0008 in place; no new ADR
**Decision:** No ADR-0012. ADR-0005 gets a dated *Amended (2026-08-28)* status line and its hook-steps bullet rewritten to the push-only hook plus host-side worktree removal. ADR-0008's consequence paragraph ("deferring the reset to once per run needs a sandcastle teardown hook, which does not exist") is replaced with the actual mechanism: sandcastle preserves a dirty worktree and runcastle removes it host-side after the run. The implementation ticket makes these edits (an ideation session cannot write `docs/adr/`, per the ADR-0011 precedent).
**Why:** The reasoning delta is one paragraph; a standalone ADR would restate ADR-0005's context to carry it. Amending keeps the isolated-workspace design readable in one place.

## 4. One lap, specced whole
**Decision:** The feature is specced in full for lap 1 — no `Later laps` section. The prompt nudge about commit cadence is already shipped by `burn-guard-and-prompt-rules` and is not duplicated here; persistent caches and commit-frequency rules stay out of scope as the brief requires.
**Why:** The change is one hook string, one host-side cleanup call on every exit path, two pinned test files, and two ADR edits — small and settled, with the design audited against every consumer of the worktree.
