Tickets and review are tools, not phases

A feature is one agent with tools, and the lead from its first message: it edits code, makes tickets, runs rounds and runs a review. There is no Go button. The agent asks in chat and starts once you say yes, and what you see is read off what is actually happening.

Under the hood

core

The phase column, PIPELINE, the planning steps and the lap columns go. A status helper derives the lane from facts: rounds, the waiting reason, ready declarations, the live session.

server

go(), the human burn, agenticReview, quickChange, complete_phase and go_feature go. dispatch_round and declare_ready stop checking the phase; declare_ready sets the waiting reason and keeps only the scenario. emit_tickets opens Work. One brief, one kickoff, no permission prompts.

web

The panel views Plan, Work, Review and Details replace the phase body. The next-step bar and the stepper go. The sidebar's Needs you reads the waiting reason. ProgressIcon replaces PhaseIcon.

skills

One feature-lead skill with reference files (tickets, rounds, planning alone, the preview, design). The separate ideate, lead, spec, tickets, revisit and design skills go; code-review stays for review agents.
