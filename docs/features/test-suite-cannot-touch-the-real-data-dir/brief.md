# Test suite cannot touch the real data dir

Isolate the whole test suite from the developer's real ~/.runcastle, and make a regression impossible to miss. Measured on the maintainer's machine: ~/.runcastle/worktrees/ held 5,385 leaked directories (almost all empty `proj_<id>/`), plus real worktrees named after test fixtures (`alpha-feature`, `beta-feature`, `kept-feature`, `busy-feature`) and a stray `~/.runcastle/ws-input-test.ts`. Cause: `dataDir()` (packages/core/src/paths.ts ~43-46) honours `RUNCASTLE_DATA_DIR` or falls back to `join(homedir(), '.runcastle')`; the root `vitest.setup.ts` only DELETES inherited `RUNCASTLE_*` vars, which forces that fallback for every test that does not opt in via `useDataDir(home)` (packages/server/test/helpers/data-dir.ts). Known unisolated: `packages/server/test/projects.test.ts` (real repos + createFeature), describe blocks in `git.test.ts` (e.g. mergeFeature ~l.1522, createFeatureBranch); probably ~50 more files (archive, draft-features, feature-list, kickoff, launch-artifacts, session-lifecycle, resolve-conflict, review-wires, research, ticket-burner, lap-kickoff, resume-reentry, waypoint-work, converge, burn-from-review; draft-features and resolve-executable set HOME/USERPROFILE but not RUNCASTLE_DATA_DIR). A prior feature already flagged this as left undone: docs/features/scaffold-commit-lands-on-the-feature-branch-not-the-checkout/outcome.md:60.

Build: (1) In `vitest.setup.ts`, AFTER the existing scrub of `RUNCASTLE_*` (keep the scrub — inherited asset vars make tests read stale migrations), set `RUNCASTLE_DATA_DIR` to a fresh `mkdtemp` dir per worker and remove it on teardown. `useDataDir` callers still override it. (2) A guard so this cannot regress: e.g. `dataDir()` throws when `process.env.VITEST` is set and it would resolve to `join(homedir(), '.runcastle')`. The guard matters more than per-file fixes; do not hand-patch test files one by one except where the guard exposes a real need. (3) In `addWorktree` (packages/server/src/services/git.ts ~690-696), `mkdirSync(dirname(path))` runs before `git worktree add`, so a failed add (e.g. `seedProject` in test/helpers/fixtures.ts:32 defaults repoPath to a non-git temp dir) leaves an empty `worktrees/<projectId>/` behind — in production too. Either create the parent only once the add will proceed, or remove the parent again when the add fails (only if empty). (4) Related leak from docs/features/scaffold-commit-lands-on-the-feature-branch-not-the-checkout/test-notes.md:58-71: create_feature tests leave a full repo checkout in %TEMP% per test per run because `tmpRepo()` dirs are never removed; add one shared helper (e.g. `withTempDataDir()` next to `useDataDir`) that creates and cleans up, and use it where the hand-rolled copies are. Do NOT delete anything already leaked in the real ~/.runcastle — a separate feature's boot sweep handles that. Use `node:path` for every path; Bun only.

Verify: full suite green, and the real data dir untouched — record entry counts (and newest mtime) of `~/.runcastle/{worktrees,sessions,reviews,logs}` before and after a full run and report both in the outcome (in a sandbox where ~ is fresh, show the dir is not created at all). Tests: the guard throws under Vitest for the real-home path; a failed `addWorktree` leaves no parent dir.
