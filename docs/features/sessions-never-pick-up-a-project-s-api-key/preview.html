Sessions never pick up a project's API key

Runcastle stops Bun from loading .env files, so no session or worker is ever billed to an Anthropic API key from a project folder. A key you export in your shell still works, and tests fail if the leak ever comes back.

The show

Where the key gets in today

Bun reads any .env in the folder a Bun process starts in, before runcastle's code runs.

Before

runcastle started in a folder with a .env
↓ Bun loads it into the server
server env holds ANTHROPIC_API_KEY
↓ copied into every child
sessions, review and fix workers, setup terminals
session adapter and hooks start in the worktree
↓ that Bun loads the project's .env
Claude Code bills the project's key

After

runcastle started anywhere
↓ boot drops what Bun loaded from .env 3
server env holds only what your shell exported 1
↓
children get no .env key
adapter and hooks start with --no-env-file 3
↓
sessions bill your subscription
your app's dev command, setup, scenarios: unchanged, still read the project's .env 4

What is left out

Later

  • A project's bunfig.toml (e.g. a preload script) also runs inside runcastle's Bun processes in the worktree: offered as a backlog feature

Not this feature

  • How sandbox workers sign in (they already get only the named token)
  • Any setting or screen for choosing how sessions are billed
  • Removing a key you exported in your shell

Under the hood

Boot. The first thing the runcastle bin does, before config loads: parse the .env files Bun would have read from the start folder. On Linux, delete each of those keys missing from /proc/self/environ (the environment before Bun's loading). On macOS and Windows, delete each whose value equals the file's (the shell wins conflicts in Bun). Log the removed names, never values. Skipped when already started with --no-env-file.

Launch helper. One module returns [execPath, "--no-env-file"] for direct spawns and bun --no-env-file run "<script>" for hook lines. Used by both runtimes' ACP launch specs, both hook writers, the adapter bundling step, and the Agent SDK side calls when claude is a JS file.

Doctor. A new info-severity probe on ANTHROPIC_API_KEY / ANTHROPIC_AUTH_TOKEN.

Not touched. Dev pane, drive hooks, scenarios, design server; ~/.runcastle/.env, read by hand. Checked unaffected: sandbox workers, the native claude binary, MCP (HTTP).

Open. A JavaScript claude CLI started by the adapter itself would still run under a Bun runcastle does not launch.
