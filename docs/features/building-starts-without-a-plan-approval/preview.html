Under the hood

No server guard ever blocked building before a yes: the approval lived only in the lead's instructions, tool descriptions, prompts and the Plan's UI. So this is a rewrite of words plus three removals.

  • Skills: feature SKILL.md rule 6 and 11, preview.md (optional page, shown with show_file), planning-alone.md's ending, design.md, decisions-and-spec.md; plan links out of the project and QA skills.
  • Server: the show_plan tool and its pre-allow go; start_worker and hand_back descriptions drop the plan; the planning run's prompt asks for decision 5's ending; a migration drops the features' plan shown/seen columns with their events, figures and mutation; old plan_shown thread events render as file cards for preview.html.
  • Web: Plan view, PlanBody, plan card, plan notices and phone screen go; NewMark/OlderMark move to a design-owned file first; /plan, /preview and feature:<slug>/plan open Details; glossary, pipeline stage and the "Plan automatically" hint reworded.
  • Checking it: server tests on the tool list, kickoff text, thread model and migration; web tests on panel views and addresses. Live sessions run the installed runcastle, so trying the lead's new behaviour needs this branch's server started by hand.
