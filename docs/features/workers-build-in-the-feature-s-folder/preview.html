Who builds what

You asked features to build on their own, with no workers, to save memory and disk.

  • The lead (me)Builds it all in this folder: the worker placement and host launch, landing with checks, the guards, the wording, the lead's rules.
  • My subagentsGuard tests on Windows command forms and the worker service tests, in parallel; then a review of the diff.
  • The reviewRun by my own subagents, not a Review worker, against the brief and the repo's standards; I fix what they find, run typecheck and the affected tests, then say ready.
  • WorkersNone started.

Worker rowNew folder column and a placement (feature-folder or own-folder); the container engine column stops being required. Old sandbox workers finish the old way.
Starting a workerBuild workers join the host path the drive workers and drive review already use: host briefing, host permissions, a real folder. An own-folder worker gets a new worktree cut from the feature branch's tip, and the project's setup command if one is set.
HandbackA feature-folder worker's commits come from the per-turn commit record the drive workers use. "Land" only marks it landed.
Landing an own-folder workerRuns the project's check commands in its folder; on green merges through the feature's landing queue and removes the folder; on red returns the output. Conflict handling unchanged.
Hook routeThe edit guard's docs-only branch becomes the lead's folder lock; workers get folder containment and a git command check modelled on the drive's checkout guard; the remote guard learns the worker's folder; the command splitter learns PowerShell and Windows paths.
ReviewA review that does not drive the app runs on the host in the feature's folder, writing only its notes.
WordsThe feature skill, worker tool descriptions, worker briefing, review template, guard refusals, web wording, and a plain risk statement in the README. CONTEXT.md lines are left for the orchestrator.
TestsThe hook route (allow or refuse per kind and folder, Windows forms) and the worker service against a temporary git repo.
