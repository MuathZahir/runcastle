Under the hood
Three kinds of new thing
MCP tools for the project session, terminal messages from runcastle, and the orchestrator's skill text. Everything else already exists.
Tools
Have a feature plan itself; read a feature in full; send a feature's session a message (a headless resume of its conversation); burn; start and stop a test drive and a project drive; record test notes; start a lap that plans itself; merge through runcastle (outcome doc, shipped state, worktree clean-up); start a draft; add to a brief. Each refuses what the human's button refuses.
Messages
Typed into the live project terminal the way a live chat is briefed today (writeToLiveTerminal), one line per event on its features. Not live: nothing is typed, and the next launch's briefing opens with what happened since.
Ownership
A feature records that the orchestrator owns it (created in the mode, or handed to it). Drives the marker, the messages, and what the tools act on.
Launch
Mode on: bypassPermissions on Claude Code, approvals never on Codex; the orchestrator briefing and skill. Mode off: today's project session, unchanged.
Headless runs
Sending back and lap planning reuse the self-planning launch (headless, Stop on the page, an exit event saying whether it finished).
