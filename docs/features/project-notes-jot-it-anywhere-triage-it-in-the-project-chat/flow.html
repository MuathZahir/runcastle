runcastle · feature plan · lap 1

Project notes: jot it anywhere, triage it in the project chat

Get a small observation out of your head in ten seconds, with no structure. Do the thinking later, in the project chat, which grills you on what the notes actually mean before anything turns into work.

1Jot→ 2Pile up→ 3Triage chat→ 4Route→ 5Burn · Merge ↺ then drive main and jot again
1 · Capture

Three doors, one popover, ten seconds

Available on every screen inside a project. The note goes to the project you're in, so there's never a picker.

  • Ctrl J (⌘J on Mac). Works even while your cursor is in a terminal.
  • Note button in the titlebar, next to search.
  • New note in the ⌘K palette.
  • One line of text, plus a pasted screenshot if you want. Enter saves, Esc discards.
  • No agent runs at capture time and nothing is analysed. It only records.

2 · The pile

A badge on the project row, an inbox on the project page

Notes are never cards in the rail. They're a count on the project row and a Notes card on the project page, just above your past conversations.

  • Open notes: edit, delete, or Dismiss. Click a thumbnail to see it full size.
  • Triaged (N): collapsed. Each note shows where it went and has a Reopen button.
  • Triage N notes starts the chat in step 3.
  • The inbox can't create work. No "→ ticket" button, by design.

3 · Triage chat

It grills you first, then routes

A note written in ten seconds records a symptom, not what you want. So the session interviews you, ideation-style, before anything turns into work.

  • How notes get in: Triage N notes opens a fresh project chat whose opening briefing says "triage the open notes". The agent pulls them live with list_project_notes, including screenshots, so a note you jot mid-chat isn't missed.
  • ① Cluster: it reads every note, plays back the themes it sees, and you correct the grouping.
  • ② Grill per theme: one question at a time, always with a recommended answer, checking what's already built or decided. Notes can be dropped, merged, or reframed.
  • ③ Route and carry: what you settled in the grilling goes into the brief or the ticket, then triage_project_note marks the note.
  • Skip a theme and its notes stay open. Defer one and the agent rewrites it into the sharper version with update_project_note.
  • A normal New chat still opens by asking what you want, and mentions "4 open notes" so it can offer triage.

A note's life

Two states, and triaged is frozen

open
  • Counts toward the badge
  • Editable, deletable (deleting also removes its screenshot)
  • What list_project_notes returns
triaged
  • Required one-line outcome, plus an optional link to a feature
  • Frozen: an honest record of what the work was built from
  • Keeps its screenshot
open → triaged the triage chat, or your Dismiss (outcome "dismissed") triaged → open Reopen, if the chat routed it wrong

Built with the future in mind

What plugs in next

project-level-test-drive

Drive main with the dev pane and video tools. Every note from the drive lands in this inbox through the same write path. Its brief gets amended in its own revisit.

project-fix-lane (parked draft)

If batches still feel heavy: one standing, feature-shaped lane per project, fed by triage one lap at a time. It's also the natural home for a future "no Burn click" setting. Only the routing text in triage.md would change.

Not in this lap

  • No "note → ticket" button in the inbox
  • No notes.md file. The chat reads rows directly.
  • No agent, diagnosis, or analysis at capture
  • No capture outside runcastle, or on the portfolio home
  • No annotation, element picking, or video on capture
  • No cleanup of old triaged notes
  • No featureless burn straight onto main
  • No changes to feature test notes or drives
