The wake message the run gets 2:

[runcastle] A server restart cut off your planning run. Carry on where you were. Uncommitted in your folder: docs/features/<slug>/decisions.md, docs/features/<slug>/spec.md

Only the planning run hears of the restart; the orchestrator learns of it when the plan arrives, as it does today 3. A cut-off run that is not woken (shipped feature, a test drive's copy) is closed the way a Stop closes one, so its chat stops declining questions.

Under the hood

Cause, confirmed: the carry-on rule in the boot reconcile (carriesOn()) skips chats with purpose self-plan. The commit that added it gives no reason; it dates from when planning was a separate one-shot process.

Change: drop the self-plan clause (keep the legacy headless one). A planning run gets its own wake message with a git status file list from its worktree (first five, then …; best effort). It is sent with source runcastle, so the planning purpose stays set and the turn's end runs the existing "planning ended" step.

A cut-off planning run that is not woken runs that same "planning ended" step at boot, marked incomplete, which clears its purpose.

Tests in the restart carry-on suite: the existing "skips a self-planning run" case flips; new cases for the file list, the not-woken close, and the end-of-turn event.
