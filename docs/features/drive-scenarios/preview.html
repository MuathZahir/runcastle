Drive scenarios

A test drive lands you in the state you want to test, already signed in, instead of on a blank app. A scenario is a file in .runcastle/scenarios/ that seeds the state and prints where to land.

Under the hood
Discovery
list .runcastle/scenarios/** in the drive checkout, skip _*; own = git diff base…branch
Run
runner command with {file}, cwd = checkout, env = RUNCASTLE_* + drive.env overlay
Read
last ENTRY_URL= on stdout; relative resolves against the drive URL
Land
drive panel navigates; event on the timeline; failure keeps output tail
  • New session kind scenario, launched in the project's main checkout (where the drive has the branch checked out), feature- or project-scoped.
  • Edit guard: whole checkout while the driven branch has no .runcastle/scenarios/; otherwise .runcastle/ only.
  • MCP tool run_scenario({ file }), scenario sessions only: same runner as the picker.
  • Host setting: the scenario runner command, beside the drive setup/stop commands.
  • Acceptance beyond dogfood: the signed-in landing proven on a real project with sign-in, after merge. 9
