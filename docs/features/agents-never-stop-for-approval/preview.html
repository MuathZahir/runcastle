Agents never stop for approval

No runcastle agent ever stops on the Allow / Reject box again. When Claude Code or Codex still asks to approve a command, runcastle answers it at once, so work left running overnight keeps going.

The show

An agent runs a command Claude Code still wants approved, for example a short Python edit fed in through a heredoc, or a git push that your own ask rule covers.

Today

Agent runs the command
↓

↓
The chat shows Allow / Reject and waits. Overnight, the epic waits with it.

After

Agent runs the command
↓
Claude Code or Codex asks
↓
Runcastle answers "allow, this once" at once 4. The command runs; the chat shows it like any other.

The same holds in every chat: orchestrator, leads, workers in and out of the sandbox, drive chats 1; for your git push rule 2; and for sandbox workers, which keep the auto modes you chose 6.

What still reaches you is unchanged: an agent asking you a question, an MCP server asking for input 5. Nothing new pings you 3.

The Allow / Reject box itself leaves the chat and the phone view 7. That is the one visible change, a removal, so there is no new screen to design.

Under the hood

Why no-approval mode still asks. Claude Code sends some requests to the host on purpose even in bypass mode: its own safety checks (heredocs, compound commands, some deletes), the user's ask rules, tools that need the user (leaving plan mode). The adapter also turns bypass mode off when the server runs as root, so then every action asks.

One place to change. Every request from every chat reaches the thread host's permission handler (onPermission), which today opens an approval ask and waits. It becomes: pick the allow-once option (the plan-exit ask: the option back to no-approval mode), write a quiet permission_allowed record to the thread log, return. Nothing writes to any settings file.

Codex chats on the host. Their config says no approvals, but their launch names no session mode, so Codex likely runs them in its asking mode. The launch sets the matching mode; the handler covers anything left.

Replaced branches. The human ask; the sandbox worker fallback that asked before MCP calls; the reject that planning-alone runs give.

Removed. The approval dock in the chat and phone views and their design states, the approval answer path, the "needs you" reason from an approval. Old thread logs still parse.

Untouched. Question and MCP input asks, the worktree and burn guards, auto mode's checker blocks.

Proof. Host tests feed each request shape and assert the option picked and that no ask opened; a hand-started reproduction from the branch's server confirms it for real.
