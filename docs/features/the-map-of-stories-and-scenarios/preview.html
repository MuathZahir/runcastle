Where main's catalogue comes from 5

The catalogue is the static build of your stories. A build takes minutes in the sandbox and never starts the app.

Under the hood
Main catalogueA place per project in the stories store for main's build: files, manifest and per-story history. Served from the stories port like the other builds.
→
Map modelA server procedure joins the build's index.json, scenarios listed at main (git ls-tree) and history into groups.
→
WebA map location (/p/:id/map[/:group]) in the router-less navigation state, the sidebar switch, and the pages.
  • The build reuses the stories build, refactored so it is no longer shaped around one feature. Promotion happens at merge, where the delete runs today.
  • Story history: the import graph gives the files each story file reaches. git log --first-parent main over them, read through Merge branch 'feature/<slug>', credits a feature.
  • Scenario history: git log over the scenario file and its .http file, cached by main's commit.
  • Every change emits an event, so the map refreshes live when a build lands.
