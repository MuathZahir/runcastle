The show

One self-planning run on a feature that adds a screen, from the moment you leave to round 1.

While you are away

It plans, then designs 1

  • Decisions, as today
  • Installs, then writes real components and one preview page per state, with sample data
  • Unsure about taste: a Tweaks menu, two choices at most 4
  • Uses the base branch’s components only 10
While you are away

It looks at its own screens 3

  • Starts the design server for a few minutes
  • Screenshots each page with agent-browser and fixes what is off
  • The server stops when the run ends
  • A screen it can’t serve: a hand mock in the plan 7
While you are away

It leaves the plan, and waits 2

  • Spec, tickets and plan preview: committed
  • Designs: not committed
  • Needs you · “designs to look at · start round 1?” 5

  • “Approved” → committed as design: …
  • “Change it” → done live, or while you’re away again 12
  • Yes to round 1 → commits what is left, then builds

Before and after

Today

A self-planned feature’s new screen is described in words or drawn as a hand mock. You first see the real look after a round has wired it.

With this

You see the real components with sample data, live, before anything is wired. Only what you approve is committed.

What was decided

Open one for the reason.

What is left out

Later

  • Batching “N designs ready” and keeping features consistent: One orchestrator, no mode
  • A limit on runs designing at once, if the cost is ever felt

Not this feature

  • Wiring designs to real data (tickets, after approval)
  • Any new button, status or auto-opened panel
  • Designing in other headless runs (lead wakes, relays)

Under the hood

Three small changes

Skill text

The feature skill

  • planning-alone.md: may install and design screens; leaves them uncommitted; checks them; never opens the design panel; the closing message names the designs
  • design.md: a short section for a run with nobody present
  • SKILL.md, rounds.md: the yes commits waiting designs first; a relay never approves one
Launcher

The briefing line

  • “plan this feature by yourself, designing its screens where it adds or reshapes them, and do not build it”
Server

The design server’s stop rule

  • The server remembers which session started it
  • A headless run’s end stops the server it started (today it stops none)
  • A server the web started, or took over, keeps running
