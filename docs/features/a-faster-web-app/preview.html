Typing

Today

Each key redraws every message in the chat and re-reads all their markdown.

work per key grows with the chat

While an agent streams, every chunk (about 8 a second) redraws everything again.

After

A key redraws only the message box. Old messages are left alone.

work per key stays tiny

A streamed chunk redraws only the message it belongs to. Every message stays on the page 7.

Refresh

Today

Every refresh downloads the whole app again, uncompressed: about 1.8 MB.

≈ 1.5 s at 10 Mbit/s before any work starts

Then every list is fetched twice, and again on each alt-tab back.

After

Compressed once, then cached by the browser. A repeat refresh downloads almost nothing; an update still shows on a plain refresh.

repeat refresh: only the page itself

Each list fetched once; the live stream keeps it current 8. Terminal, design view, command palette and phone QR load when first opened 9.

Under the hood

Typing. The thread column holds both the draft and the transcript, so each key re-renders every item and re-runs react-markdown with remark-gfm and remark-breaks. Nothing in the web app uses React.memo. Fix: draft state moves into the composer's own subtree; transcript and items memoised on item identity; Markdown memoised on text with hoisted plugins; the thread fold reuses the unchanged prefix so a streamed chunk changes one item; localStorage draft write debounced (flushed on send and on page hide); the @ file query debounced.

Refresh. The static route reads each file per request with only a content-type header; gzip covers only /api/trpc. Installed build: one 1.66 MB script (476 KB gzipped) plus 122 KB CSS. Fix: precompressed in-memory static files (br/gzip), immutable on hashed /assets/*, no-cache + ETag on index.html; React.lazy for xterm, design view, cmdk palette, QR; a vendor chunk via Vite 8's rolldown options; the live stream's first onReady stops calling the 28-family resync; refetchOnWindowFocus off for stream-covered queries.

Measuring. scripts/thread-timing.ts grows typing and load measures with CDP CPU and network throttling, and a Linux Chrome path. Tests: server tests on the static route's headers and 304s; a unit test that the fold keeps unchanged items' identity; a happy-dom component test counting message renders per key.
