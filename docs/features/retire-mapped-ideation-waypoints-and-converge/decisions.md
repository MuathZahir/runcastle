# Decisions — Retire mapped ideation (waypoints and converge)

## 1. Full removal, not a soft retire
**Decision:** Mapped ideation is removed outright. That covers `escalate_to_map`, `emit_waypoints` and `resolve_waypoint`, the `waypoint` and `converge` session kinds and their skills, ideate §3, the research-waypoint workflow, the map UI (MapRail, WaypointCard, the map next-step branch), the `waypoints` table and `features.mapped`. Git history is the archive.
**Why:** Only 5 of 153 features were ever mapped, and none since 2026-08-28. The two real ones, in the runcastle project, both shipped as single features. The project session already cuts big intent into several features, each with its own laps and merge. A soft retire, which would close only the entry point, keeps all of the carrying cost: two session kinds, per-kind tool filtering and UI branches, with none of the simplification.

## 2. Existing mapped features convert silently to ordinary features
**Decision:** The migration drops `features.mapped` and the `waypoints` table, rows included. Every formerly mapped feature becomes an ordinary feature, with no legacy state. Their `map.md`, `research/` and `prototypes/` stay on disk as plain history: they surface under `moreDocs` and are no longer canonical. `map.md` leaves `AGENT_DIGEST_DOCS` and the burner's map trimming. The pinned view of a shipped feature stops showing a map rail. The three demo features still in planning simply resume as ordinary planning features, and nothing is auto-deleted.
**Why:** Nothing real is mid-flight. Both runcastle mapped features shipped, and the three demo ones have their waypoints resolved or dropped. The resolved answers already live in `map.md` and `decisions.md`, so dropping the rows loses nothing. A read-only "legacy mapped" freeze would keep map code alive forever, which undoes decision 1.

## 3. The project session is the size gate, and it runs a shape grill before cutting
**Decision:** "Too big for one session" is caught at the project session, before a feature exists. Big intent never reaches ideation as one feature. Before proposing a cut, the project session runs a **shape grill**: one question at a time, each with a recommendation, breadth-first across the main ideas and never deep into any one. It asks only what could change the cut: the pieces, which one is the core, where the human is unsure and what they would test-drive first, and roughly how wide each piece is, including whether it needs research or a prototype. It stops at the cut. It locks no decisions and writes no feature docs. What it learned goes into each feature's brief, covering what the feature is for, what it must not swallow, what is understood and what is still open, so ideation starts warm. Every feature it creates must be thinkable in one ideation window; a piece that is not gets cut further or parked as a draft. The project skill's "advisor, not a griller" stance becomes "shape griller, not design griller". Design questions such as data shapes, UX details and edge cases are still handed to the feature's own session.
**Why:** Splitting big intent into several features is the job maps did, and the project session is already the one surface that cuts features and can see the whole portfolio. Today's cut is made with no grill at all, so it misjudges size. A breadth-only grill gives the cut real information without duplicating ideate's design grill.

## 4. Feature dependencies are their own feature, parked, not part of this retirement
**Decision:** The replacement for a waypoint's `blockedBy` ordering is a stored merge-order dependency between features: a draft can depend on other features, draft or started, that must merge before it can be worked on. It ships as its own feature, `feature-dependencies-merge-order-gates`, parked as a draft with a brief that carries the open design questions and the needed ADR amending `feature-grouping-forking-and-referencing` decision 24. This feature does not build it. Until it ships, the project session records the order between the features it cuts as prose in their briefs.
**Why:** The retirement is a large mechanical deletion with its design settled. Dependencies are small in code but carry real design questions: what is gated, what "merged" means for forks, archived dependencies, and rail display. Those deserve their own grill. Neither feature depends on the other.

## 5. Ideation has no escalation branch; a feature that turns out big is absorbed by laps
**Decision:** Ideate §3 (escalation) is deleted outright, with nothing in its place: no routing back to the project session and no self-splitting. The "probe the size early" instruction aimed at mapping goes too. If a feature turns out bigger than expected mid-grill, the existing slicing question handles it: a thin lap 1, with the deferred scope parked under the spec's `## Later laps`. `create_feature(draft)` in ideate stays exactly as it is, for scope creep only. The revisit skill and ADR-0010 lose their "escalate via ideate §3" lines in the same way: an oversized lap defers into later laps.
**Why:** The project session's shape grill (decision 3) is the size gate, so an oversized feature in ideation is rare. Making the human switch sessions for the rare case costs more than it saves. Laps already absorb "too much for one pass" without a new mechanism.

## 6. The AFK research workflow is deleted with the maps
**Decision:** The research-waypoint workflow goes: `workflows/research.ts`, its burner prompt, the `research` model step and the `runcastle/research/` branch prefix. Nothing replaces it. Sessions research inline with subagents, and a question too big for that becomes a spike feature cut by the project session.
**Why:** Only research waypoints can trigger it, so without maps it is dead code. Inline subagents already cover the need without a sandbox, a branch, a merge or a model step. A new standalone research trigger would be a new feature, not something that rides a retirement.

## 7. Nothing replaces the single converged spec
**Decision:** When big intent is cut into several features, each one gets its own spec, laps and merge, and no cross-feature spec replaces the converged one. Cross-feature truth lives where it already lives: ADRs and the charter for durable decisions, the feature index and work record for what shipped, briefs for the reasoning behind the cut, and, once it ships, feature dependencies for order. Features that must land together use the existing fork mechanism: a fork merges into its parent and rides the parent to main.
**Why:** `spec.md` is never read across features (grouping feature, decision 8), so a converged spec coordinated nothing beyond the one feature it described. The cost is the loss of one atomic branch for the whole intent, a trade already accepted by choosing independent features over maps (decision 1).

## 8. The record: ADR-0012 supersedes ADR-0001, SPEC §13 goes, and the charter sentence is corrected in the same change
**Decision:** A ticket writes `docs/adr/0012-retire-mapped-ideation.md`, recording decisions 1, 3, 5 and 7 in short form. ADR-0001's status is stamped `superseded by ADR-0012` in place and the file stays on disk. `docs/SPEC.md` §13 is deleted. ADR-0010 and ADR-0009 lose their map and converge mentions; ADR-0010's "escalate via ideate §3" becomes "defer into later laps". The same change rewrites CONTEXT.md principle 7's mapped-ideation sentence to say big intent is cut into several features by the project session after a shape grill (ADR-0012).
**Why:** The "only the project session writes the charter" rule governs who authors charter content. This edit authors nothing: it corrects a sentence the merge itself makes false, and leaving it would have the charter describe machinery that no longer exists.

## 9. Old data keeps loading: session kinds are rewritten, events are left alone, stale config keys are ignored
**Decision:** The migration that drops `waypoints` and `features.mapped` also rewrites session rows of kind `waypoint`/`converge` to `chat`, so `SessionKind` shrinks with no legacy values. Past events (`waypoint.*`, `research.*`, `feature.escalated`) are left as they are. A `stepModels` key for `waypoint`, `converge` or `research` in an existing `config.json` is ignored on load, never an error.
**Why:** History must stay readable and no install may fail to boot after upgrading. Rewriting the kinds is cheaper than carrying a tolerant enum forever, and the kind only matters for launching, which these sessions will never do again.

## 10. One lap, specced whole
**Decision:** The feature is specced whole and expected to merge on lap 1, sliced into tickets layer by layer (schema and migration, server, skills, web, docs).
**Why:** The design is settled and the operator is sure. The size is mechanical deletion, not uncertainty.
