Under the hood

The contract file

// .runcastle/stories.json, committed in the project
{
  "build": "bunx storybook build -c .runcastle/storybook --stats-json -o {out}"
}
// {out}: where runcastle wants the static build. The build writes
// index.json (every story, its id and source file) and
// preview-stats.json (the import list) there.

Where things live

  • ~/.runcastle/stories/<featureId>/: the feature's latest build, or its failure log. Replaced each pass, removed at merge.
  • ~/.runcastle/stories-base/<commit>/: branch-point builds, shared by features with the same branch point, removed when nothing unmerged uses that commit.
  • The build runs in the gate sandbox's worktree, and its output folder is copied out before the worktree is cleaned up, since nothing copies files out of a sandbox today.
  • Port 4514: a static file server (traversal-guarded, like the web app's) with no API. Each frame loads Storybook's single-story URL, iframe.html?id=<story>&viewMode=story.

Prepare and planning

  • The prepare skill gains a UI-states step and one recipe file in its references: official setup into .runcastle/storybook/, providers, edge data faking, one page story, a stories typecheck recorded as a verify command, reuse of an existing Storybook, and one build on the host as evidence.
  • Prepare's write guard widens from .runcastle/ + .gitignore to also allow the package manifest and lockfile.
  • get_feature_context reports whether stories are set up on the base. The tickets skill gains a "ship a story" block mirroring "ship a scenario", and the one-time "Prepare can set up UI states" mention.
