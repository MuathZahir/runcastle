The review: one, sized to the change

Always one review 3An ordinary worker with runcastle's own instructions and an empty conversation. It checks the diff against your words and the repo's standards.
Drive only if users meet it 9A screen, a command, an API, a library's public functions: use it as a user would. Otherwise it reads.
Second review rarely 2Only after more than a handful of fixes, or fixes outside the feature's code. Scenarios still come before "ready" 10.

Agents talk less: assignments quote your words, handbacks are short, and the lead brings the base branch in before review and before ready 4.

Who builds what

  • Server and web: one feature file (on its own, Sonnet): the merge stamp, the old-shape check, "add to the brief", the reviewer's empty start and required review kind, prompt wording, the merge dialog, tests.
  • Me: the rules: the feature skill and its pages, the review instructions, the code-review, qa and project skills, the worker's handback wording. It is wording that follows the decisions, so it is quicker to write than to explain.
  • The review: a reading review, since no screen changes; you then try it on the branch's own server, because skill changes reach live sessions only after a publish.

Under the hood

One pure helper in core says whether a feature folder is old-shape (it has decisions.md or spec.md). The merge step, the orchestrator's "add to the brief" tool and prompt wording branch on it; the docs list and agent digest already show whatever files exist.

The outcome composer gains a short form. For a one-file feature the merge step appends it to brief.md as ## Review summary in the existing runcastle: outcome commit, and the epic's merge news points there.

start_review requires the kind (drive or read). The reviewer's feature read drops the lead's latest turns. The review templates and the code-review skill read the brief's words and decisions, falling back to spec.md for old features.

Tests: the outcome composer, the merge step on a temp repo (both shapes), the review assignment renderer, the reviewer's read, and the skill-text tests.
