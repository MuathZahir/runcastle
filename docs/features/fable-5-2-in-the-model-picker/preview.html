What happens when you pick it

  • New chat: it starts on Fable 5.2.
  • Running chat: the next message runs on Fable 5.2, like any other switch 4.
  • If Claude Code refuses the model, the chat shows its usual error and stays usable 5.
  • Codex chats follow the same rule 6; older versions sit under "Older models" 7.

Who builds what

  • Me (the lead), alone. A short hands-on test first to see how Claude Code accepts a model it does not list, then the server change and its tests. No workers: it is a small server-side fix.
  • Review at the end, driving a real chat: pick Fable 5.2 in a new chat and in a running one.

What was decided

Open one for the reason.

What is left out

Later

  • Nothing parked.

Not this feature

  • Any redesign of Settings or the picker.
  • New model features: hiding models, per-chat lists, testing models before listing them.
  • Changing how Settings discovers models.

Under the hood

The picker's list is the runtime's saved model catalog: what Claude Code last reported. Settings' list (the roster) only added 1M variants to it, so Fable 5.2 never got in.

List: the catalog function adds every roster model the saved catalog lacks, labelled the way Claude Code labels models ("Fable 5.2"). The picker itself is untouched.

Making the pick take: Claude Code's adapter refuses to switch a session to a model it does not list. A hands-on test picks one of two routes. Preferred: runcastle tells each session to list the roster's models too (the availableModels setting), so switching works through today's path. Fallback: a pick the session does not offer restarts the chat's session on the new model, keeping the conversation. If neither holds, I stop and come back to you.

Tests: the catalog tests (one expects exactly 3 models after Claude Code reports) and the request-builder tests change; a real chat checks the answer comes from Fable 5.2.
