Move runcastle to another machine

One command moves your projects, feature list, chats, notes and unfinished work from the PC to the VPS. The PC is only read, so a failed move loses nothing.

The show

No new screen. You run a command, then open the same app on the VPS.

What goes and what stays 12

Goes

  • Projects, features, tickets, reviews, notes
  • Chats, including ones you started by hand in these repos
  • Claude memory for these repos
  • All branches and uncommitted work
  • Settings, except burn width and CPU limits

Stays, and the report says so

  • Secrets: .env files, logins, Codex auth
  • Other ignored files, listed by name 14
  • Global Claude rules, skills and settings
  • Claude's file undo checkpoints
  • Talk worktrees, which rebuild themselves

After the move

Start the server on the VPS. Open chats resume where they stopped 6. Run Prepare on the listed projects 7, recreate the .env files, and stop working on the PC 9.

What is left out

Later

  • Nothing deferred. The marker that stops the PC server is a small addition if you want it.

Not this feature

  • Keeping two machines in sync
  • Backups, the VPS itself, the installer
  • Rewriting history text
  • A Windows destination
  • Any new screen
  • Pushing to any remote

Under the hood

New server module: scan, pack, unpack, around a small pure core. No schema, API or web changes.

scan

  • Read-only database connection
  • Git status of each checkout
  • move-in --check over ssh

pack

  • VACUUM INTO for the database
  • git bundle --all per repo
  • Patch and file copies per checkout
  • Manifest with hashes and row counts

unpack

  • Stage, rewrite, verify
  • Swap into place
  • Apply uncommitted work
  • Write move-report.md

Claude folders are renamed by Claude Code's own rule: every character outside a-z, A-Z and 0-9 becomes a dash. Existing boot handling ends stale sessions, and talk worktrees rebuild when a session opens. A real chat resume on Linux is still unproven and is the first thing the rehearsal checks.
