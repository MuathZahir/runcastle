How an epic gets its name 12

New epic: "I want refunds and…"→ The orchestrator's first reply names the chat: Payment System→ It may rename while young, say when it cuts its first feature→ Your rename always wins

On ship day, one short model run names each chat listed then, once 13. A request that does not fit the name gets "start a new epic?" 19

Who builds what

Epic names and the new-chat fix start at once. The epic list waits until the orchestrator says "Every feature has one owner" has landed its origin chat field; then that branch is merged in here and the list starts.

Epic listWires the designed list into the sidebar on every page and the phone, the shelves' epic names, the epic crumb, and "Orchestrator" to "epic" in the words on screen. Starts once the owner feature's field is in.on its own

Under the hood
feature.list + thread.list

group by origin chat · listed? · yellow first→ SidebarEpics
replaces the Orchestrator card + in-motion lanes
  • Membership reads the origin chat field from "Every feature has one owner"; this feature adds no field. A chat is listed while active by today's rule or while any feature it cut is in motion or up next (origin replaces holding).
  • A new MCP tool, for orchestrator sessions only, sets the chat's own title as a title event marked as the orchestrator's. Naming order: your rename, the orchestrator's name, the runtime's title, the first message. Refused once you renamed.
  • "Asking about <feature>" reads the link from the owner feature's chat-asks rule; with none it reads "Asking you".
  • The new-chat fix starts from a reproduction: the likely causes are a first send that never logged a prompt on that chat, or the list hiding chats while a feature is open.
  • Seams: the epic ordering and SidebarEpics (new, tier-1 tests); the listed-chat rule and thread naming (existing tests extended); the naming tool via MCP; thread.list; the feature header crumb.
