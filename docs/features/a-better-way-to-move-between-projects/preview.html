Who builds what

  • Me — the saved order on the server: a position per project, new ones at the end, a reorder call that updates every open window, with tests.
  • Project rail on its own — builds the rail and phone row from the approved design: real needs-you dots, drag to reorder, Alt+1–9, the sidebar head without the dropdown.
  • All projects page on its own — rebuilds the All projects page from its approved design, in rail order. Runs beside the rail worker; they touch different files.
  • Review at the end — drives the app, runs the checks, and hands you the Review Package.

Not this feature

  • Running work on the rail (it stays on All projects)
  • Per-project colours or icons
  • Dots or shortcuts in the Ctrl+K palette (it only follows the rail order)
  • The "Open a project" flow and onboarding
  • The sidebar's own content, beyond swapping the dropdown for the name

Under the hood
  • Server — a position column on projects (migration backfills today's order); the project list sorted by it; opening or reopening puts a project last; project.reorder({ projectIds }) takes the full ordered list, refuses a mismatch, emits project.reordered.
  • Needs you — the same rule as the sidebar and the tab-title count, read from the per-project feature lists the tab title already polls. No new polling.
  • Web helpers — pure, unit-tested: rail tiles (initials, needs-you, shortcut number), move-in-list for the drag, Alt+Digit → index.
  • Layout — the rail mounts in the shared frame before the sidebar, so it survives Ctrl+B and shows on All projects; the phone row tops the phone list screen.
  • Keys — one window handler for Alt+Digit1..9 (by key code, so macOS Option works); the chat terminal's key mapper intercepts Alt+digit so it never reaches the session as ESC+digit.
  • Retired — the dropdown switcher and its test.
