How it gets built

Small enough to build in the lead's own chat: no worker tickets, then one review round.

Lead builds: the fold rule, the two chat components, a seeded chat to review on→ Typecheck and tests→ Review round: drives real chats, Review Package with screenshots→ You test-drive and merge

What was decided

Open one for the reason.

What is left out

Later

  • Dropping the "write the whole answer after your last tool call" workaround from agents' notes, once this ships

Not this feature

  • How agents are prompted
  • How thinking is shown, beyond folding with the tools
  • Promoting thinking into the reply (a reply that only existed in thinking stays unseen)
  • The composer, ask dock, cards and the changed-files card's own look

Under the hood

One rule in one place: core's thread fold (foldThread), which the server and the web share.

Today: segments → split at the LAST real tool call → [one work fold] [questions pulled out] [answer]

After: segments → walk in order → words · fold · words · card · words · fold … · changes card

  • Each stretch of text segments becomes one agent item; talk-only calls (wait_for_you, show_file…) still show nothing and do not split words.
  • Each run of tools, thinking and subagents becomes one work item with its own time; live only while it is the turn's last item.
  • The asked item and the narration step retire; item ids stay stable while a turn streams so open folds stay open.
  • Web: WorkBlock folds one run (thinking-only runs as one "Thought for"); AgentMessage shows Branch and the model only on a turn's last words.
  • A scenario seeds a project chat with a multi-stretch turn and a ladder turn, for the review and the test drive.
  • The chat's Copy / Save Markdown and a branched chat's preface use the same fold, so they carry every word too.
