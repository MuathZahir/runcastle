# Flow redesign: ideation through tickets

## Problem

Between "a feature card exists" and "the human clicks Burn", the app offers two doors for most actions and none for the one that matters most. The next-step bar says *Resume grill* while the ended-session card below it says *Resume session*; a mapped feature stranded at spec shows three differently named ways back in; a mapped ideation with open waypoints — the state a newcomer most needs guidance in — has no solid action at all, only a ghost override. The map rail names its groups after internal states (*frontier*, *blocked*) and hides the record of what was worked behind closed disclosures. The spec phase shows a one-line card with a peek button while the bar claims "the spec takes shape beside the conversation". At tickets, the terminal sits at a fixed-height guess with the ledger below the fold, and the only way to pick which model burns a ticket is a select buried inside a text editor two clicks deep — the human did not know it existed. Pinned "read-only" views are the live view with two buttons hidden: they still mount the live terminal with *End session*, still offer *Work* on waypoints, and their empty states point at a bar that has been replaced by a banner. Lap 2 shows *Burn 11 tickets* counting every lap while the server burns only this one. And the vocabulary — grill, converge, frontier, fog, promote, revisit — meets the user unexplained at every button. Roughly a thousand lines of the retiring stylesheet belong to these surfaces.

The two goals the human set (decision 1): the flow must make sense to someone who has not read the docs, with **no state in which there is no correct next action**, and the model each ticket runs on must be **choosable in the UI**.

## Approach

**The bar is the single door** (decisions 3, 8). In ideation, spec and tickets every session action — start, resume, resume converge, converge, burn — lives only in the next-step bar, and the bar offers exactly four kinds of solid action: start/resume a session, **Work next**, **Converge**, **Burn**. Nothing crosses a gate by hand: the `Promote to spec` / `Approve spec → tickets` secondaries and the mapped `Override & converge…` form are deleted (server procedures untouched, their removal deferred). The body never repeats a door: the ended-session card becomes a quiet status line, and the in-body converge-recovery bar becomes a bar state (*The converge session ended before the spec and tickets were written* → **Resume converge**). Because the shell flow makes the Inspector's gate card read-only, the bar's description is where the gate's reason is stated in plain words. Live states stay status-only.

**The bar's states, by phase.** *Ideation*, resolved in this order: lap ≥ 2 with no lap-N session → *Work lap N* / **Start lap N session**; lap ≥ 2 live → status; mapped with all waypoints terminal → **Converge**; mapped with open waypoints → **Work next** targeting the lowest-seq ready waypoint, the button label fixed and short, the waypoint's title and the orientation line ("3 of 10 waypoints done · 2 ready to work — next: *{title}* · pick a different one in the map", plus *Still unspecified: …* when the map has fog) in the description; mapped, ready list empty but a research run in flight → status *Waiting on N research run(s)*; live → status; ended conversation on disk → **Resume session**; never started → **Start session** (decisions 4, 9, 12). *Spec*: live → status (*Writing the spec*); converge-stranded (mapped, no live session, no spec, no tickets) → **Resume converge**; otherwise → **Resume session** / **Start session** with "no spec yet" as the reason. *Tickets*: this lap's tickets ≥ 1 → **Burn N tickets** with the ghost **Ask for changes** (a revisit session, shown only when idle); zero and live → status *Emitting tickets*; zero and idle → **Start/Resume session**. Every count the bar or ledger shows is the current lap's (decision 9).

**Artifact on the left, terminal on the right** (decision 11). All three live bodies share one layout. The left pane, by state: mapped ideation → the map rail; unmapped ideation → `decisions.md` rendered as it accrues, headed *Decisions so far · N*; spec → `spec.md` rendered in full and refreshing as it is written. The pane reuses the rail's chrome — collapsible to a strip, choice persisted globally — at about 380px (the map rail stays 300px). Its header carries a **docs menu** (`decisions.md ▾ · brief · map · spec`) that swaps what the pane renders, replacing the Inspector's Knowledge list for these phases (decision 15). The right pane is the terminal at full height. The spec doc card and its peek go; `DocPeek` survives for the Inspector.

**The map rail is a progress checklist** (decision 5). Header `MAP · 3/10 done` with a progress strip and a ⓘ that glosses "waypoint". Groups in order ready → working → waiting → done; each card leads with a plain-word state chip — *Ready*, *Working* (pulsing), *Waiting on "{blocker title}"*, *Done* — with the type demoted to dim mono; ready cards open by default and carry **Work** / **Resume** (the one deliberate exception to the single door: choosing a different waypoint than the bar suggests is a choice only the rail can offer). The collapsed strip shows `3/10`; the `0 FRONTIER` stub is gone. The rail renders only at ideation. The done-state strip on the terminal only reports *Resolved ✓ — {summary}*; its own *Work next* button goes.

**Tickets: the terminal is a strip, the ledger owns the model** (decisions 6, 7). The tickets body is a vertical stack. With zero tickets and a live session the panel is open at full height; once tickets exist it starts collapsed to its one-line strip (`Ideation session · live · 8 tickets emitted · Show terminal`), remembered per feature until the session ends, and the ledger takes the body. On every pending or failed row, the model chip is an inline menu — `default model ▾` or `{model} · {runtime} ▾` — listing the configured roster grouped by runtime and saving on change through the existing partial ticket edit; burning/done/cancelled rows show it static. Beside the ledger's sandbox and default-model chips sits **Model for all pending ▾**, applying one choice to every pending ticket in the current lap. The in-place editor keeps title, goal, context and acceptance. The expanded row's actions are **Edit ticket** and **Cancel ticket** (inline confirm; cancelled rows stay, dim), pending/failed only, hidden while pinned. A ledger-header docs menu replaces Knowledge here too.

**A pinned phase is a frozen record** (decision 10). The read-only banner carries a one-line phase summary derived from the events feed and the docs (`Ideation · 2 days · 3 sessions · 12 decisions`, `Spec · written 2d ago`, `Tickets · 11 emitted, 11 done`). Pinned ideation renders `decisions.md` inline, the map with its done group open when mapped, and a quiet list of the sessions that ran; pinned spec renders `spec.md` inline; pinned tickets shows the ledger with lap headers and no session strip. No terminal, no End/Work/Edit/Cancel anywhere in a pinned view; the live session appears only in the current phase. Empty cases state what happened (*No spec — this feature was created as a quick change and skipped ideation.*).

**Lap-awareness** (decision 9): the lap check precedes the mapped check in the ideation resolver; the server's mapped G1 check gains the rule the doc gates already have from lap 2 (a lap-N ideation/revisit/converge session must exist) with a reason of the same shape; every ticket count is lap-scoped, with earlier laps under their collapsed `Lap N` headers.

**Session strip and stepper** (decision 13). The strip reads `{Kind} session · ● live · 14 min` with the kind in plain words, the id in a tooltip, **End session** a ghost with no confirm; launching shows `● starting…`, the 30-second check-in hint and the briefing banner unchanged; ended reads `{Kind} session · ended 2h ago`. Stepper chrome is the shell's; tooltips change: done steps carry the phase summary and "click to review", the current step says what the phase is for, upcoming steps say what unlocks them.

**Details panel** (decision 15). In these three phases the Inspector starts collapsed — one initial-default constant beside the shell's persisted preference; the human's toggle wins thereafter. It is not removed.

**Vocabulary** (decision 12). Burn, Converge, waypoint and lap survive as names with tooltips from the shared vocabulary module; grill, frontier, fog, promote and approve are retired from every string this flow renders; `Revisit` becomes **Ask for changes** with a description; `SESSION LIVE` replaces `GRILL LIVE`.

**Visuals and code shape** (decisions 14, 16). The approved prototype is the reference — the app's tokens, the 8/16/24/32 rhythm, exactly one solid button per view. The grill body splits by surface (body, artifact pane, map rail, waypoint card), the tickets body likewise (body, ledger, row, editor, a shared model menu), the session panel into strip and panel. Derivations are pure modules with tier-1 tests; the collapsible strip, the model menu and the editor get tier-2 DOM tests. Every legacy stylesheet rule this surface owns is migrated to utilities and deleted with the ratchet lowered, dead selectors included; the Inspector's gate-card block stays with the shell flow. Workspace changes are confined to the phase-body dispatch and the action switch; the shell flow (`feature/flow-redesign-project-shell-and-navigation`, in build) lands first, and flow 7 lands after this one and owns build → shipped.

## Seams

- **Next-step resolvers** (existing; `nextStep` and its per-phase resolvers for ideation, spec, tickets). Input: feature, sessions, tickets, gate, map content; output: kicker, title, description, at most one solid action, secondaries. Every state in decisions 3, 4, 8, 9 and 12 is a test row here; the invariant "no state returns a solid action that the body also offers" is asserted by construction because the body no longer derives doors.
- **Artifact selection** (new, pure). Given phase, mapped flag, pinned state and the docs on disk, which document the left pane renders, its heading and count, and which docs the docs menu lists. Observes decisions 5, 10, 11, 15 without a DOM.
- **Map progress and groups** (existing `waypointGroups`, widened). Adds the done count, the ready/working/waiting/done state words, the blocker title for waiting cards, the lowest-seq ready waypoint the bar targets, and the "open by default" rule that differs between live and pinned views.
- **Phase summary** (new, pure). Events + docs + sessions + tickets in; the one-line summary for the read-only banner and the done-step tooltip out (duration, session count, decision count, spec written-at, tickets emitted/done per lap). The place the "what happened" facts are derived, so the banner and the stepper never disagree.
- **Lap-scoped counts** (existing lap-account derivation, widened). Ticket counts for the bar and ledger header scoped to the current lap; asserts *Burn N* equals what the burn procedure will act on.
- **Ticket edit and cancel** (existing wire procedures). The row model menu and the bulk menu call the partial edit with `model` alone; Cancel calls the existing cancel. Observed by the ledger's tier-2 tests and the existing service tests.
- **Mapped G1 gate check** (existing, widened server-side). From lap 2 requires a lap-N doc-writing session, same shape as the doc gates; observed by the existing gate tests.
- **Rendered surfaces** (existing test pattern). Tier-1 static markup for the bar, the artifact pane, waypoint cards, the ledger rows and the read-only banner in every state; tier-2 DOM tests for the collapsible session strip, the model menu (single and bulk), the editor and the cancel confirm.
- **Vocabulary module** (existing). The single source for the tooltip sentences; the retired terms are asserted absent from the rendered strings of this flow's components.

## Out of scope

- The Inspector itself, its gate card, Activity feed and titlebar toggle — the shell flow's; only the initial-collapsed default for these phases is touched here.
- The stepper's chrome, the header, the sidebar, the palette, the status bar — shell.
- Build, review, test drive, merge, the run view and the shipped body — flow 7. The tickets body as rendered at implementation-with-no-run keeps working but is not redesigned beyond what the shared ledger gives it.
- Gate and phase semantics (charter decisions 7 and 8, ADR-0001, ADR-0010) and the skills that drive the sessions — reflected, not changed. The one server-side change is the lap rule on the mapped G1 check, consistency with the existing doc-gate rule.
- Server-side deletion of `advance`, `overrideGate`, the converge override and their tests — deferred cleanup.
- A read-only transcript viewer for feature sessions.
- Drag-to-resize for the artifact pane or the session strip.

## Open questions

- Exact artifact-pane width: start from the prototype's 380px and tune in review; the map rail stays at the existing 300px token.
- Whether the "remembered per feature" strip state at tickets should be session-scoped (reset when a new session starts) or feature-scoped — start session-scoped, as decided; revisit if it surprises.

## Later laps
