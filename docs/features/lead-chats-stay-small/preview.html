Under the hood
  • Compaction already exists. The context meter's "Compact now" button sends the runtime's /compact as a hidden prompt through the thread host's turn queue, and the chat already draws a divider for it. Nothing calls it automatically today.
  • Three new triggers on the thread host: at the end of a self-planning run (thread lifecycle), at the idle stop (30 min), and before a turn after a 55-minute gap. Each checks: feature lead, context above 150k, no turn or queued message pending.
  • The ceiling is Claude Code's auto-compact window (env var CLAUDE_CODE_AUTO_COMPACT_WINDOW=200000) in the Claude runtime's launch env for feature leads; Codex's own limit where its runtime honours it.
  • Quiet by design: a compaction's turn end skips notifications, orchestrator news, the self-plan ending and waiting-state changes. It records its trigger and sizes on the compacted event for the divider.
  • Skill edits stay in the delegation guidance, "Build it the cheapest good way", the planning-alone survey and screenshot steps, and one grilling paragraph, since "Tools and skills say less" edits the same files.
  • Built by the lead, not workers: one server change and some skill text, too small and too tangled to split. Then one review round (code review; nothing new to drive beyond the divider).
