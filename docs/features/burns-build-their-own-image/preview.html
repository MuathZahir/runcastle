Burns build their own image

The first burn builds the sandbox image when it is missing, with no click and no command to run. A server with no browser gets a small command for the same build.

Two burns at once

The server runs one build at a time. The second burn waits, sees the image, and carries on. 7

Settings and doctor

A missing image reads “not built yet: the first burn builds it”. The Build image button stays for anyone who wants to build ahead. 6

Under the hood
prepareImageBuildThe plan, moved out of the router. Button, burn and command all call it.
runImageBuildRuns a plan with no terminal: streams to a log, stops after 10 quiet minutes, can be aborted.
withImageBuildSlotThe server's one-at-a-time queue.
ensureBurnImageThe burn step, after the auth, root and engine checks, before the toolchain probe.
Traps in the burnerMemoised engine commands, the run's project snapshot, and a stored image whose Dockerfile has gone. See spec.md.
Who builds itThe lead, in its own window. No tickets. Proved on a real engine.
