Under the hood

Server

Keeps each read thread's parsed events and reads only new lines. One copy serves thread reads, thread lists and the waiting flag. Large answers are compressed.

Web

One read per thread at a time, never cancelled, with one more after the last signal. One read to open, not two. Thread reads go on their own requests.

Status

One rule in core. awaitingInput stays true after a turn, so a waiting reason still wins. The chat's own state does not change.

Order

A timing script first, for a baseline against the targets. Then reads, opening, page load and status. Same script, typecheck and tests last, then the review.
