After Conductor, don't settle for another agent runner.

runcastle teamNov 5, 20262 min read

On November 4, Conductor announced it is joining Meta. If your agents lived there, you need a new home. Before you pick the next app that runs ten agents at once, ask whether more agents was ever what you were missing.

Agents don't need more prompts. They need a process.

Conductor solved the easy half

Conductor gave every task a workspace: a git worktree, a branch and an agent, with plan mode and a code review panel. The rest was yours. You decided what to build, wrote a prompt for each workspace, and ran the app to see if it worked. Every workspace you added was one more to supervise. Parallel agents make you faster at writing prompts. They don't make you faster at shipping.

runcastle runs the project, not just the agents

In runcastle you bring an idea, not a prompt. A feature's agent talks it through with you, cuts the plan into tickets and waits for one word: yes. Then rounds of sandboxed workers build the tickets in parallel on the feature's branch while you're somewhere else.

It checks the work before you do

When the round lands, a review agent boots the branch, clicks through the feature, records a walkthrough and reports what is wrong. The feature's agent fixes it. By the time you look, you're test driving a working app, not reading a 2,000-line diff.

And it isn't Mac-only

runcastle runs on macOS, Windows and Linux, and on your phone. It drives Claude Code or Codex on the subscription you already pay for. Every plan and decision lands in your repo as plain markdown, so nothing is stranded if a tool goes away.
